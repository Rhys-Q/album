# 实现与资料来源

## 分层

- `components/epd/frame.c`：EPF1 验证、CRC-32/ISO-HDLC、生成测试图、逻辑到原生旋转和双控制器行数据转换，无 ESP-IDF 依赖。
- `components/epd/epd.c`：厂家寄存器初始化、SPI 协议、刷新和关机状态；HAL 注入使同一驱动可在主机模拟测试。
- `main/board.c`：真实 GPIO、SPI3 mode0、4096 字节内部 DMA 缓冲、BUSY 中断、确定的接口断电状态。
- `main/main.c`：串口命令，PSRAM 帧缓冲，验证完整嵌入照片后才允许开启屏幕；命令由单一 REPL 任务串行执行。
- `tools/convert_photo.py`：电脑侧处理照片；不引入设备端图像解码或文件系统。

HAL 中 `select(mask)` 的 bit0/bit1 对应主从；SPI 数据不自动插入命令，命令作为首字节发送。片选可跨多笔行事务保持，读回时发送3个零字节产生时钟，rxlength 始终对应当前块。自动片选为 -1，未使用 GPIO0。

## 状态与错误

启动屏幕关闭。显示入口先验证整帧及旋转参数，再 power/reset/init，传送两半，PON、DRF、POF逐步等待 BUSY 低→高，最后深睡、停SPI、接口低、EN低。上电后两个片选先置高，再复位。

每次命令前清 BUSY 边沿记录。未看到置忙，即使一直读到高也不会报告完成。前一事务未空闲则拒绝开始下一条电源命令。BUSY 的延迟/脉冲范围仍需逻辑分析仪实测。普通 GPIO 中断和任务轮询不构成硬实时测量保证。

错误返回 -1 IO、-2超时、-3数据或状态无效、-4故障锁存。SPI/BUSY故障触发有界异常清理、锁存，禁止自动刷新重试。`off` 不解锁。HAL 关机尽量执行所有动作，错误仍尝试 EN 低，不用 abort/reset 跳过收尾。`powered` 只记录软件请求，不是供电电压检测。

屏幕不正常响应时无法证明 POF/深睡可执行，故障关断不能承诺高压安全放电。当前硬件无隔离，软件也无法覆盖电源意外掉电和 MCU 崩溃。

## 厂家依据与差异

来源为用户归档 `docs/raw/GDEP133C02-ESP32 code example.zip`；归档与实际读取文件的 SHA-256 在 `vendor-source.json`。初始化顺序、寄存器值、主从选择、DTM每行300字节分半及PON/DRF/POF沿用该示例；加入既有项目已采用的深睡07/A5。

没有复制厂家图像或旧build，没有声称厂家授予新的源码再分发许可。使用资料原有权利边界不变；项目代码明确记录派生的寄存器依据。

修正：原例自动片选默认0、无限忙等待、读分块rxlength错误、错误不传播及刷完没有完整输入断电处理。并非将其他型号电子纸的 LUT 套用于本屏。

数据源：`docs/raw/GDEP133C02.pdf`、硬件接口/供电约定、厂家示例。面板批次、温度适用、VCOM和完整时序仍按现有硬件设计的实测边界执行。
