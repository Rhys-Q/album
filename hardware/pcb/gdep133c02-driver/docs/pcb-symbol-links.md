# KiCad 元件关联修复（2026-10-08）

当前电路仍为 v0.5-GDRC-DEBUG。本次只修正原理图符号到 PCB 封装的关联，不改变电路功能、器件数量或制造几何。

此前生成脚本把 PCB 封装 path 写为 `/根UUID/分层页UUID/符号UUID`。KiCad 10.0.6 实际前向更新使用 `/分层页UUID/符号UUID`，导致默认更新把现有 129 个器件识别为待新增。原理图实例路径包含根UUID是正常的；错误在于把这个前缀也用于 PCB 的符号关联。ERC/DRC和按位号检查网络能够通过，不能代替实际 GUI 更新兼容性检查。

正式 PCB 已移除 129 个 path 中多余的根UUID。当前GUI预览记录在 `reports/update-preview.txt`，访问记录在 `reports/gui-open.json`。首次修改以精确文本替换完成；原有封装、位号、位置、旋转、焊盘、网络、走线、过孔、板框和铜区保持原设计。

一次性生成/迁移脚本已随历史文件清理；保留的 `scripts/check_design.py` 中包含独立检查：用 KiCad 导出网表的 sheetpath 和符号 tstamps 校验每个 PCB 关联路径，同时拒绝重复位号，避免把相同错误作为预期值重复验证。

正式工程已通过 KiCad GUI 更新预览验证：**“根据参考位号将封装重新链接到原理图符号”保持关闭，不新增、不替换、不删除封装，也不再要求修正符号关联。** 预览仍会同步图纸名称、图纸文件和元数据，数量多不表示重复创建元件。未执行该预览里的字段更新，因为它们不属于此次关联修复。

预览中 FPC1 焊盘61/62两条警告来自底座的机械固定焊盘：它们没有原理图信号引脚，不是漏接屏幕的第61/62个信号；本板屏幕接口仍为60针。不得为消除警告随意把固定焊盘接到某个信号。固定焊盘的结构与电气要求仍须按连接器图纸/实物复核。

完整 ERC 0；DRC 0、未连接0、原理图一致性问题0；129个关联通过新检查。制造文件重新导出为 [v0.5-linkfix 审阅包](../releases/jlc-cn-review-v0.5-linkfix-2026-10-08/README.md)。该旧包现已由v0.6制造审阅包替换，历史文件通过Git恢复。仍未完成硬件性能验收。
